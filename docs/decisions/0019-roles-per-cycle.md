# 0019 — Four cycles, one role each, and five story states

[README](../../README.md) · [Decisions](index.md)

**Status:** accepted (2026-11-01)

## Decision
The process is four cycles, each run by one role skill that stops at its
hand-off:

- **Product** — `/sanchin:product-owner`: mission → epics → narratives →
  stories, a grill at each level; writes each story's scenarios tagged
  `@pending`; places stories in the roadmap's milestones; hands them over
  **ready**.
- **Planning** — `/sanchin:tech-lead`: a ready story → one plan per
  component, technical grill, cross-check; hands it over **planned**.
- **Delivery** — `/sanchin:developer`: a planned story → worktree,
  scenarios red, green, reviews, close, merge; **implemented**.
- **Architecture** — `/sanchin:architect`: a technical idea (refactor, new
  tool, architecture change) → technical grill → decision record →
  technical stories, which enter the same roadmap through the product owner.

A story's states are pending → ready → planned → in progress →
implemented, and the validator checks what each requires. A role that
finds its input open sends the story back one owner. The roadmap is a set
of milestones; their story tables are generated by the validator.

## Alternatives considered
- **One developer skill for the whole loop** (the 0.1.0 design): one role
  decided the "what", the "how" and the code in a single run, and the user
  approved all three at once, or none.
- **Roles chained automatically**: faster, but each output would be built
  on before the user saw it.
- **Plans by the architect**: keeps one technical role, but mixes the
  per-story design with changes to the architecture itself, which need a
  different scope and a decision record.

## Why
Each cycle ends with a decision that belongs to someone: what to build, how
to build it, that it is done, how the system should change. One role per
cycle makes each decision explicit, gives each artifact one author, and
lets the validator say whose turn it is from the story's state. Technical
work goes through the same roadmap because it competes for the same time.
